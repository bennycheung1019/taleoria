# 逐步建立世界與分層記憶

新世界先建立「可玩的開場＋短篇故事骨架」，確認後即可開始。詳細章節、未接觸人物與場景留待探索時建立。一般遊玩仍共用原本的一次 GM 生成，不為每個路人或每一章另外呼叫模型。

## 開局與章節

1. 建立主角、一名在場人物、起點與最多一個附近地點。文字保持精簡，保留玩家明確的能力與世界偏好。
2. 準備核心衝突、三項固定真相、三個簡短章節方向及起點的一個可選線索，不預寫遠方角色、完整章節或未發生的對白。
3. 玩家確認後才建立正式戰役。實際探索時，GM 在同一次回覆中先列出新人物基礎（`establish.people`）與章節備註，再呈現敘事並保存其他變更。需要的新地點與通路也一起保存。首次使用某章時可在同一回覆私下準備一小段；日常閒聊不推進章節，回合數不觸發強制進度。
4. 展章與推進分開記錄。建立線索不代表玩家接受，也不代表必須進入下一章。拒絕、失去線索、繞路與提前解決都持續保存。

展章只能追加資料，不可藉此覆寫固定真相、既有地理、重用機會 ID 或取消人物死亡。GM 的自然語言理解仍受模型能力限制；結構檢查無法保證它永遠不會用不同措辭重複線索。

如果開場完成、骨架生成失敗，`data/library/drafts/` 會保存未確認開場的檢查點。相同偏好與模型網址的重試可從骨架續接；更改偏好或網址會重新建立。最多保留八份未完成檢查點，不含正式世界；成功後移除該檢查點，下個新世界不會重用同一開場。此資料夾含私人偏好，不應公開上傳。

## 酒館與人群

| 資料層次 | 如何處理 |
| --- | --- |
| 背景人群 | 在地點的 `crowd` 用短文字記錄活動與氣氛，不逐人寫傳記 |
| 臨時互動人物 | 接觸時建立穩定 ID、身分、外觀、態度、所知與簡單牽掛，標為 `incidental` |
| 持續登場人物 | 交往深入時補充為 `developed`，保留原身分、記憶與關係，不重新抽角色 |

每回合預設選取四名現場人物的完整資料，其他人只保留短索引；明確指名者可超過預設數量。索引有長度上限，未載入的人仍在存檔中。按名字、外觀描述與近期接觸排序回取，不把「未載入」當成「不存在」。文字比對不是完整語意檢索，描述模糊時，具體稱呼會比較可靠。

重要承諾可保存為附本輪敘事證據的私人記憶。相關舊記憶與近期記憶一起取用；再次提到已知人物時，也會從事件簿回取較舊的對話原文。群體反應不需要模擬每名酒客，同處一室不自動代表聽見所有私語。

## 哪些記憶會釋出

遠處地點、暫時沒走的路線、其他章節細節與未互動人物的完整資料會退出模型上下文，仍保存在遊戲電腦的 SQLite 與事件簿。再次相關時才取回，沒有刪除正式世界紀錄的自動程序。

本版不在玩家閱讀時額外啟動 LLM 模擬整個世界，也不自動卸載模型。精簡上下文減少的是送入模型的內容，不等同立即釋放模型權重或作業系統配置的全部記憶體。

舊存檔不需要轉換，原有完整章節、人物、地點與後果仍保留；選擇性載入亦適用。快速開局只影響之後建立的新世界。完整搬機或 `.rpgsave` 匯出／載入會保留故事與人物記憶。
